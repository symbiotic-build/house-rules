`version: 1` selects the metadata format. The inventory's one `specification` entry classifies the Markdown source. Document identity `example` is the prefix used by assignment selectors. The title names the reading entry; purpose, audience, scope and non-goals describe what the teaching contract covers.

The single section `main` starts at anchor `example` in the source. Its seven role names declare tour, behavior, obligations, choices, questions, lookup and evidence in that order. `example#main` selects that complete subtree. Its summary states the reader's outcome. Empty prerequisite and dependency arrays request no other explanation, and the empty scenarios array registers no separate scenario.

The navigation path points to the same source. Region identity `example` selects its marker pair. Status `draft` declares no approval. The empty `test_runners` array keeps the built-in Python unittest default; other languages add a runner through the [metadata contract](source-formats.md#metadata). Approval requires the authority and decision described there.

A batcher prevents overfilling by accepting items only while its batch has room.

| Key | Value | Status | Basis |

Submit up to [2](#capacity); a full batch retains its items on refusal.

<a id="req-capacity"></a>
### Requirement: refuse a full batch

This obligation preserves existing items when a caller exceeds the batch capacity.

**Actor:** [Batcher](#batcher).

**Condition:** A submitted item would exceed [2](#capacity) items.

**Result:** Return `Full` without changing the batch.

**Verification:** Inspect the batch after refusal.

**Tests:** [Full batch](#test-capacity).

**Status:** specified.

**Basis:** [Teaching decision](#decision).

<a id="failure-full"></a>
### Failure state: full batch

This refusal tells the caller how to submit an item after the batch fills.

**Trigger:** Submission would exceed [2](#capacity) items.

**Outcome:** The caller receives `Full`.

**Retained state:** Existing items remain unchanged.

**Recovery:** Submit the item in a new batch.

**Authority:** The submitting caller may start a new batch.

**Verification:** [Full batch](#test-capacity).

## Generate and check

Initialize and verify the three files with the shared tool; no local checker copy or profile file is needed. Here `HELPER` names the pinned `spec_docs.py` path and `REPOSITORY` names an independent empty directory. Use Python from the tool's locked environment. Save the three files there before running:

```sh
git -C REPOSITORY init -q
python HELPER generate --root REPOSITORY
python HELPER check --root REPOSITORY
```

Generation reports `docs/example.md` and exits `0`; checking reports `0 errors, 0 warnings` and exits `0`. The [capacity correction](tour-fixing-a-wrong-capacity.md#capacity-repair) owns the deliberate mutation and repair walkthrough.

An assignment file containing `{"version":1,"sections":["example#main"]}` selects the complete chapter. Run `python HELPER context --root REPOSITORY --assignment FILE` to emit its registry, metadata, profile, source and provenance.
