# Specification and design-document system

The specification and design-document system helps authors keep technical contracts in Markdown and give readers checked navigation to their explanations. The shared Python tool also prepares complete reading material for assigned agents. Reviewers use that material to assess behavior and evidence beyond what structural checks can establish.

Which authored inputs become navigation and complete agent reading material?

```mermaid
flowchart TD
    A["Markdown: meaning and declarations"] --> C["Shared Python tool"]
    B["Metadata: identities and reading order"] --> C
    C --> D["Generated navigation"]
    C --> E["Complete registry and selected explanations"]
    D --> F["Human and agent review"]
    E --> F
```

## Overview

Write implementable technical contracts with one authored authority, checked structure and complete agent reading material.

**Audience:** Specification and design-document authors, reviewers and tool implementers familiar with Markdown links, headings and basic Git snapshots.

**Scope:** Single-file and multi-file specifications and designs; source authority, declarations, navigation, checking, review and snapshot-bound agent context.

**Non-goals:** Product contracts, HTML publication, a renderer, expression evaluation, semantic measurement conversion, independent requirement stores and general prose formatting.

Markdown owns technical meaning and literal values. Shared metadata identifies those explanations and orders them for readers. Navigation and agent reading material derive from both sources, so authors repair the sources and rebuild the outputs. The diagram shows that path through checking to review; the generated map identifies where each explanation belongs.

The document assumes familiarity with Markdown headings, links and basic Git snapshots. Read the map to choose a chapter, or continue with the [tour](tour-fixing-a-wrong-capacity.md#tour) for the complete author-facing repair. The mechanism chapters explain why the repair works. The reference chapters then provide exact inputs and commands, while [Acceptance evidence](acceptance-evidence.md#acceptance) identifies what proves the system's obligations.

## Continuing example

This example gives the reader one concrete contract to follow through authoring, checking and review. The [bounded-batch fixture](../../../skills/spec-writing/scripts/fixtures/minimal/docs/example.md) describes a synthetic component that accepts items while its batch has room. Its teaching authority approves no production behavior.

The [batcher home](../../../skills/spec-writing/scripts/fixtures/minimal/docs/example.md#batcher) contains the definition and a capacity of [2](../../../skills/spec-writing/scripts/fixtures/minimal/docs/example.md#capacity) items. Capacity counts items in one batch. When a caller submits a third item, the [full-batch refusal](../../../skills/spec-writing/scripts/fixtures/minimal/docs/example.md#failure-full) returns `Full` and leaves the existing items unchanged. The submitting caller can submit the refused item in a new batch.

The [capacity requirement](../../../skills/spec-writing/scripts/fixtures/minimal/docs/example.md#req-capacity) states that obligation. Its reciprocal [inspection case](../../../skills/spec-writing/scripts/fixtures/minimal/docs/example.md#test-capacity) checks the refusal and retained items. This is a declared inspection of a teaching contract; the fixture contains no running batch service.

The tour introduces a documentation defect by changing only a displayed link:

```markdown
Submit up to [3](#capacity); a full batch retains its items on refusal.
```

**Entities in this example:** [batcher and capacity](../../../skills/spec-writing/scripts/fixtures/minimal/docs/example.md#batcher).

The link still targets the capacity row, whose value remains [2](../../../skills/spec-writing/scripts/fixtures/minimal/docs/example.md#capacity). Checking reports `D10`, the diagnostic for a displayed value that differs from its home. Correcting the label repairs the documentation; it changes neither the capacity nor the meaning of `Full`. The [tour's correction](tour-fixing-a-wrong-capacity.md#capacity-repair) follows that repair through regenerated navigation and selection of `example#main`, the fixture's complete registered section.
